# PRD: 스캔앤고 (편의점 무인계산대 상품 인식)

- 작성자: 임우진
- 작성일: 2026-10-06
- 버전: v0.1

---

## 1. 한 줄 소개

바코드를 찍지 않고 계산대에 물건을 올려놓기만 하면, 카메라가 상품을 알아보고 금액을 계산해 주는 편의점 무인계산대.

## 2. 왜 만드는가

지금 무인계산대는 손님이 상품마다 바코드를 찾아서 하나씩 찍어야 한다. 물건이 여러 개면 시간이 걸리고, 바코드 위치를 못 찾아 헤매는 경우도 많다.

스캔앤고는 물건을 올려놓는 것만으로 계산이 끝나게 해서 계산 시간을 줄이고 줄 서는 시간을 없애는 것이 목적이다.

## 3. 누구를 위한 것인가

| 사용자 | 필요한 것 |
| --- | --- |
| 손님 | 물건을 올려놓으면 바로 금액이 뜨고, 빨리 계산하고 나갈 수 있어야 한다 |
| 점주·직원 | 인터넷이 끊겨도 계산이 멈추지 않아야 하고, 따로 관리할 일이 적어야 한다 |
| 본사 운영팀 | 매주 나오는 신상품을 전국 매장에 쉽게 반영할 수 있어야 한다 |

## 4. 목표

- 상품 5개를 올렸을 때 1초 안에 금액이 뜬다.
- 매장 인터넷이 끊겨도 계산이 계속된다.
- 전국 편의점 3,000곳에 설치한다. (매장당 하루 결제 약 600건)
- 매주 추가되는 신상품 50개를 그 주 안에 인식할 수 있게 한다.

## 5. 주요 기능

1. **상품 인식**: 계산대에 올린 상품 여러 개를 카메라로 한 번에 인식한다. 대상은 상품 2,000종이다.
2. **금액 표시**: 인식한 상품 목록과 합계 금액을 화면에 보여 준다.
3. **오프라인 동작**: 인터넷 연결 없이도 인식과 금액 계산이 된다.
4. **신상품 업데이트**: 새 모델을 손님이 적은 밤에 자동으로 내려받아 적용한다.
5. **바코드 스캔 병행**: 인식이 안 되는 상품이나 장비 고장에 대비해 바코드 스캔도 쓸 수 있게 한다.

## 6. 요구 조건

| 항목 | 조건 |
| --- | --- |
| 속도 | 상품 5개 기준 1초 이내 |
| 오프라인 | 인터넷이 끊겨도 계산 가능 |
| 프라이버시 | 손님 얼굴이 일부 찍힐 수 있으므로 영상을 매장 밖으로 보내지 않는다 |
| 모델 | 약 250MB, 상품 2,000종, 매주 50종 추가 |
| 비용 | 매장당 AI 박스 150만 원 |

## 7. 구현 방식: 엣지 컴퓨팅

상품 인식은 매장에 설치한 AI 박스에서 처리한다. 클라우드는 새 모델을 만들어 매장으로 내려보내는 데만 쓴다.

엣지로 정한 이유는 다음과 같다.

- 오프라인: 클라우드 방식은 인터넷이 끊기면 계산이 멈춘다. 이 조건 때문에 클라우드는 쓸 수 없다.
- 속도: 사진을 서버로 보내고 받는 시간이 없어서 1초 조건을 맞추기 쉽다.
- 프라이버시: 영상이 매장 안에서만 처리된다.
- 비용: 2년째부터 클라우드보다 싸다. (10번 항목 참고)

## 8. 성공 지표 (KPI)

자료에 조건이 나와 있는 것은 그대로 목표로 삼았고, 자료에 없는 것은 따로 표시했다.

| 구분 | 지표 | 목표 | 측정 방법 | 근거 |
| --- | --- | --- | --- | --- |
| 속도 | 상품 5개 인식 시간 | 1초 이내 | 계산대 기록 | 자료 |
| 오프라인 | 인터넷이 끊긴 동안 계산 가능 여부 | 계산 중단 없음 | 회선 장애 시간과 결제 기록 비교 | 자료 |
| 신상품 | 신상품이 매장에 반영되는 기간 | 1주 이내 (매주 50개) | 배포 기록 | 자료 |
| 보급 | 설치 매장 수 | 3,000곳 | 설치 현황 | 자료 |
| 비용 | 결제 1건당 비용 | 약 1.5원 이하 | 5년 총비용 ÷ 5년 결제 건수 | 계산 |
| 정확도 | 상품 인식 정확도 | 99% 이상 | 인식 결과와 실제 상품 비교 | 임의 설정 |
| 배포 | 밤사이 배포에 성공한 매장 비율 | 99% 이상 | 배포 기록 | 임의 설정 |
| 사용 | 바코드 스캔으로 넘어간 결제 비율 | 5% 이하 | 계산대 기록 | 임의 설정 |

정확도, 배포 성공률, 바코드 전환 비율은 자료에 기준이 없어서 임의로 정했다. PoC에서 실제 값을 측정한 뒤 다시 정한다.

## 9. 검증 계획 (PoC)

전국 3,000곳에 설치하기 전에, 엣지 방식이 실제 매장에서 조건을 만족하는지 소규모로 먼저 확인한다.

| 항목 | 내용 |
| --- | --- |
| 매장 수 | 시범 매장 10곳 |
| 기간 | 4주 |
| 장비 비용 | 150만 원 × 10곳 = 1,500만 원 |
| 예상 결제 건수 | 10곳 × 하루 600건 × 28일 = 약 16.8만 건 |

매장 수와 기간은 자료에 없어서 임의로 정한 값이다.

검증 항목과 통과 기준은 다음과 같다.

| 검증 항목 | 방법 | 통과 기준 |
| --- | --- | --- |
| 속도 | 상품 5개를 올리고 금액이 뜰 때까지 시간 측정 | 1초 이내 |
| 오프라인 | 매장 인터넷을 일부러 끊고 계산 시도 | 계산이 정상적으로 됨 |
| 모델 배포 | 매주 밤에 새 모델을 10곳에 배포 | 다음 날 영업 전까지 전 매장 적용 |
| 신상품 인식 | 매주 신상품 50개를 추가하고 인식 테스트 | 추가한 상품이 인식됨 |
| 프라이버시 | AI 박스에서 밖으로 나가는 데이터 확인 | 영상이 외부로 전송되지 않음 |

진행 순서는 1주차에 설치, 2~3주차에 실제 운영과 측정, 4주차에 인터넷 차단 테스트와 결과 정리다.

결과에 따라 이렇게 결정한다.

- 모두 통과하면 전국 설치를 진행한다.
- 속도가 1초를 넘으면 모델을 가볍게 하거나 AI 박스 사양을 다시 검토한다.
- 배포가 밤사이에 끝나지 않으면 바뀐 부분만 보내는 방식으로 바꾼다.
- 오프라인에서 계산이 안 되면 설치를 보류하고 원인을 먼저 해결한다.

## 10. 비용과 기대 효과 (ROI)

엣지 방식은 클라우드 방식과 비교해 5년 동안 84.5억 원을 아낀다. 5년 ROI는 약 169%이고, 투자금은 약 21개월 만에 회수된다.

자료에는 비용만 있고 스캔앤고로 버는 돈은 없어서, "클라우드로 했을 때보다 얼마나 아끼는가"를 이익으로 보고 계산했다.

| 구분 | 엣지 | 클라우드 |
| --- | --- | --- |
| 처음 드는 비용 | 150만 원 × 3,000곳 = 45억 원 | 없음 |
| 매년 드는 비용 | 모델 배포 1억 원 | 인식 요금 19.7억 원 + 회선 증설 7.2억 원 = 26.9억 원 |

| 기간 | 엣지 누적 | 클라우드 누적 | 엣지가 아낀 금액 |
| --- | --- | --- | --- |
| 1년 | 46억 원 | 26.9억 원 | -19.1억 원 |
| 2년 | 47억 원 | 53.8억 원 | 6.8억 원 |
| 3년 | 48억 원 | 80.7억 원 | 32.7억 원 |
| 4년 | 49억 원 | 107.6억 원 | 58.6억 원 |
| 5년 | 50억 원 | 134.5억 원 | 84.5억 원 |

- 5년 ROI = (134.5억 원 - 50억 원) ÷ 50억 원 = 약 169%
- 투자 회수 기간 = 45억 원 ÷ (26.9억 원 - 1억 원) = 약 1.74년 = 약 21개월
- 결제 1건당 비용 = 50억 원 ÷ 5년 결제 약 33억 건 = 약 1.5원 (매장당 하루 약 910원)

계산 시간이 줄어서 생기는 효과가 매장당 하루 910원보다 크면 스캔앤고 자체로도 이익이다.

장비 수리·교체 비용과 매출 증가 효과는 자료에 없어서 넣지 않았고, 장비는 5년 동안 쓴다고 가정했다.

## 11. 이번에 하지 않는 것

- 손님 얼굴 인식이나 손님 식별
- 카드 결제 승인 방식 변경 (기존 결제 시스템을 그대로 쓴다)
- 도난 방지, 재고 관리 기능

| 위험 | 대책 |
| --- | --- |
| 매주 3,000곳의 모델을 바꿔야 한다 | 밤에 자동 배포한다. 배포 비용 연 1억 원은 이미 반영했다 |
| 아직 등록되지 않은 신상품은 인식하지 못한다 | 바코드 스캔으로 계산할 수 있게 한다 |
| AI 박스가 고장 날 수 있다 | 고장 중에는 바코드 스캔으로 전환하고 장비를 교체한다 |
